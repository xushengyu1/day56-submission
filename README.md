# AI 失物招领匹配与认领复核系统

> 题目编号：题 01  
> 当前状态：需求诊断与 PRD Review，尚未进入方案确认和编码阶段。

## 项目名称

AI 失物招领匹配与认领复核系统

## 一句话介绍

用 AI 缩小失物与招领记录的候选范围并核验拾得者预设的隐藏问答，高可信申请自动进入待交接，异常申请由管理员复核，最终交接由拾得者确认并留痕。

## 我们认为真正问题是

- 主要用户和利益相关方：作为失主或拾得者的注册用户、统一审核异常申请的管理员，以及检查证据链的评委。AI 是系统能力，不是用户角色。
- 最核心冲突：提高匹配效率与防止冒领之间的冲突；解释越具体，越可能泄露验证答案。
- 最大约束：两天内必须交付服务端和 Web 前端组成的可运行最小系统，并留下真实过程证据。
- 我们优先解决的目标：跑通“失主/拾得者输入 -> 公开候选和冲突 -> 隐藏问答 -> 自动或人工路由 -> 联系交接 -> 拾得者确认 -> 结果追溯”一条主线。

## 最终方案

PRD V0.6 已确认，技术方案尚未确认。下一阶段通过 `docs/design_option.md` 与模板要求的三方案取舍材料完成选择；当前不把 AI 初步建议当最终方案。

## 最小原型

- 原型形态：一个服务端 + 一个包含失主、拾得者、管理员视图的 Web 前端。
- 运行或访问方式：尚未实现；实现后补充可复现命令。
- 可演示主路径：注册登录 -> 发布记录/隐藏问答 -> 生成候选 -> 失主认领 -> 高可信自动待交接或管理员复核 -> 展示拾得者联系方式 -> 拾得者确认已认领 -> 查看审计链。

## AI 使用概览

- 澄清阶段：AI 已从题面提取信息分级、人工裁决、失败处理等隐含约束，并生成 P0/P1 澄清问题。
- 方案阶段：PRD 已确认，待开始真实方案对比并记录选择过程。
- 反证阶段：已审查初版 PRD 过度产品化风险；后续还需反驳最终候选方案。
- 实现阶段：尚未发生。
- 验证阶段：已把隐藏答案泄露、模糊匹配和 AI 不可用列入验收；实际测试结果待实现后填写。
- 已拒绝或修改的 AI 建议：已移除“九个页面”和“多认领并发控制作为 P0”等超出最小证明目标的建议，详见 `docs/ai/accepted-and-rejected-ai-advice.md`。

## 端到端系统设计摘要

| 层 | 本项目设计 |
|---|---|
| 前端/客户端/小程序 | 计划使用单个 Web 前端承载普通用户视图 |
| 管理端/审核端 | 同一 Web 前端中的管理员复核视图；这是角色视图，不是额外技术端 |
| 服务端/规则层 | Python + FastAPI 服务端负责候选处理、权限边界、认领状态和审计 |
| 数据层 | PostgreSQL 保存四级结构化业务数据与审计记录，pgvector 保存公开文本向量；图片使用 MVP 文件存储 |
| AI 参与位置 | 公开候选匹配、隐藏问题质量检查、回答语义核验；满足多重门槛时可自动路由到待交接，但不确认实际交接或法律归属 |
| 失败处理 | 至少演示字段不足/冲突/AI 失败中的一个，并保留真实结果 |
| 日志和证据 | 记录输入、处理依据、AI 建议、人工决定和最终状态 |
