# 8–10 分钟演示脚本

演示只使用 E2E seed 生成的合成账号、号码与图片。

## 0:00–1:00 系统边界

说明五类、五地点、公开描述与隐藏核验信息的分离；明确候选相似度不是所有权证明，身份证不用 LLM 判断。

## 1:00–2:00 注册与登录

注册普通用户、退出并重新登录。打开浏览器存储面板，说明 token 仅在内存，刷新后需重新登录。

## 2:00–4:00 OTHER 主路径

1. 拾得者发布“其他”物品并填写公开描述与隐藏特征。
2. 失主发布同类同区记录。
3. 展示 A101 候选高于 A201，类别/区域干扰项未出现。
4. 回答隐藏问题，进入待交接后才显示联系方式。
5. 切回拾得者确认线下交接，展示最终状态。

## 4:00–6:00 身份证安全路径

1. 拾得者上传合成证件图，明确确认完整号码并手工框选脱敏区域。
2. 展示公开页只有脱敏图和掩码。
3. 失主输入正确号码进入待交接。
4. 另一个候选连续输入两次错误号码，展示锁定和人工复核入口。

## 6:00–8:00 管理员与主动复核

1. 普通用户访问管理员接口被拒绝。
2. 管理员处理 claim review。
3. 管理员对 unmatched review 推荐候选，强调推荐后仍需分类型核验。
4. 打开审计日志展示两条管理员决定。

## 8:00–9:00 安全证据

展示跨用户原图 404、owner 200；说明完整号码仅存在于专用请求体，URL、页面、浏览器持久存储和普通 payload 均无泄漏。

## 9:00–10:00 可复现性与限制

展示 244 个后端测试、110 个前端测试、4 个 E2E 和 Alembic `0010` 单 head。明确当前 E2E 使用 mock AI/embedding，不声称真实外部模型效果，也不证明现实世界所有权或证件真伪。
