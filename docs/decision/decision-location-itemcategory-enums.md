# 决策：地点枚举与物品类别枚举定义

- **日期**：2026-07-17
- **状态**：✅ 已确认（前后端联调前对齐）
- **决策者**：项目团队
- **影响文档**：`prd.md`、`docs/design/end-to-end-system-design.md`

---

## 背景

前端页面已实现地点下拉框和物品类别下拉框，但 PRD 和设计文档中未定义具体枚举值，前后端联调时可能产生不一致。本次决策将前端已使用的枚举值正式写入文档基线。

---

## 决策一：地点枚举（`location_public`）

### 枚举值

| 枚举值 | 说明 |
|---|---|
| `宿舍区` | 学生宿舍楼区域 |
| `食堂` | 校园食堂 |
| `教学楼` | 日常上课教学楼 |
| `科教楼` | 科研/实验楼 |
| `图书馆` | 校园图书馆 |

### 决策理由

1. 校园场景下高频地点覆盖完整，5 个选项足够 MVP 演示。
2. 固定枚举避免自由输入导致的地点不一致（如"一教""一号教学楼""教学楼1"），便于后端标准化和匹配评分。
3. 前端已按此实现，后端 seed 数据也使用相同值。

### 后端要求

- `location_public`（PUBLIC）保存中文枚举值原样返回前端。
- `location_normalized`（MATCH_ONLY）保存标准化代码用于匹配评分，不返回前端。
- 地点接近度评分按 PRD 7.4.1 的映射表执行。

---

## 决策二：物品类别枚举（`public_category`）

### 枚举值

| 枚举值 | 对应 `item_type` |
|---|---|
| `电子产品` | `OTHER` |
| `证件卡片` | `IDENTITY_DOCUMENT` |
| `服饰配饰` | `OTHER` |
| `学习用品` | `OTHER` |
| `其他` | `OTHER` |

### 决策理由

1. 5 个类别覆盖校园常见物品类型，用户选择直观。
2. `证件卡片` 是唯一映射到 `IDENTITY_DOCUMENT` 的类别，其余均映射到 `OTHER`。这确保了核验流程分支的确定性。
3. `public_category` 用于**候选匹配硬过滤**（5 种类别各自独立匹配）和前端展示，确保电子产品不会匹配到学习用品等跨类别物品。

### 后端要求

- `public_category` 保存枚举值，用于候选匹配硬过滤和前端展示。
- `item_type` 由后端根据 `public_category` 自动推断：`证件卡片` → `IDENTITY_DOCUMENT`，其余 → `OTHER`。
- 候选匹配硬门槛使用 `public_category`（5 种精确匹配），不使用 `item_type`。
- `item_type` 仅决定认领核验分支（身份证件用 HMAC，其他物品用隐藏问题），不影响候选匹配范围。

## 决策四：地点接近度分档

### 分档规则（PRD 7.4.1 已确认）

| 条件 | 得分 |
|---|---:|
| 同一地点 | 20 |
| 同楼/相邻建筑 | 14 |
| 同校园邻近区域 | 8 |
| 明显无关 | 0 并标记冲突 |

### 地点对映射表

| 关系 | 地点对 |
|---|---|
| 同一地点 | 任意地点与自身 |
| 相邻建筑（14 分） | 教学楼 ↔ 科教楼；食堂 ↔ 宿舍区 |
| 同校园邻近（8 分） | 教学楼 ↔ 图书馆；食堂 ↔ 教学楼；宿舍区 ↔ 图书馆 |
| 明显无关（0 分） | 宿舍区 ↔ 科教楼；食堂 ↔ 科教楼；食堂 ↔ 图书馆 |

### 决策理由

1. 相邻建筑判定基于校园实际布局：教学楼和科教楼通常相邻，食堂和宿舍区同属生活区。
2. 同校园邻近指步行可达但不属于相邻建筑的地点对。
3. 明显无关指距离较远且无合理移动路径的地点对。
4. 此映射表为 MVP 初始规则，后续可根据实际校园布局调整。

### 地点匹配两层机制

地点评分分两层叠加：
- **粗匹配（20 分档）**：下拉框枚举值比较，同值 20 / 相邻 14 / 邻近 8 / 无关 0
- **细匹配（50 分语义分的一部分）**：拾得者和失主填写的详细地点描述（如"教学楼B区3楼楼梯口"）通过 embedding 向量计算语义相似度

即使失主记错楼层或具体位置（如填写"教学楼三楼"而拾得者填写"教学楼B区二楼楼梯口"），下拉框同值拿 20 分，详细描述语义接近拿语义分，不会因楼层差异排除候选。
