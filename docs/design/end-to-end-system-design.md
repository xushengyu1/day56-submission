# 端到端系统设计

> 状态：尚未进入详细设计阶段。以下只记录 PRD 已确定的系统边界，不提前填写技术实现；方案确认后由 `design.md` 和本文件同步落地。

| 模块 | 说明 |
|---|---|
| 用户端/前端/小程序 | 一个 Web 前端中的普通用户视图：输入/选择记录、查看候选、回答验证问题 |
| 管理端/审核端 | 同一 Web 前端中的管理员角色视图：查看隐藏核验材料、确认/驳回、查看追溯链 |
| 服务端/规则层 | 独立服务端；具体框架、候选算法和接口待方案确认 |
| 数据层 | 模拟失物/招领、隐藏特征、认领与审计数据；具体存储待设计 |
| AI 能力 | 仅辅助候选、理由、冲突、缺口；实现路线待比较；不裁决所有权 |
| 日志与证据 | 追溯输入、处理方式、AI 输出摘要、人工决定和最终状态 |
| 失败处理 | 至少覆盖信息不足、冲突、越权和 AI 不可用；具体策略待设计 |

## 数据流

```text
公开记录输入 -> 候选规则/AI 辅助 -> 用户查看并提交核验回答
-> 管理员读取隔离的隐藏特征 -> 人工确认/驳回 -> 审计留存
```

## 关键接口或伪接口

| 接口/动作 | 输入 | 输出 | 失败情况 | 负责人 |
|---|---|---|---|---|
| 记录输入 | 公开字段 + 隔离的隐藏字段 | 记录 ID | 缺字段、非法类型 | 待分工 |
| 生成候选 | 源记录 ID | 结构化理由/冲突/缺口 | AI 超时、信息不足 | 待分工 |
| 提交认领 | 候选 ID + 用户回答 | 待复核申请 | 越权、状态无效 | 待分工 |
| 人工处理 | 申请 ID + 决定 + 理由 | 最终状态与审计事件 | 越权、理由缺失 | 待分工 |
