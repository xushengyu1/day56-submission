# 假设与非目标

| 类型 | 内容 | 原因 |
|---|---|---|
| 假设 | 项目根目录确定为 `E:\A-xiaomi\xiaomi\2\day6` | 用户明确要求所有交付写入该目录 |
| 假设 | 最少实现服务端 + Web 前端两个技术端 | 用户明确基础要求；普通用户/管理员是同一前端中的角色视图 |
| 假设 | 使用不含真实个人信息的模拟失物/招领数据 | 作业允许模拟数据，且更适合稳定复现边界样例 |
| 假设 | 候选匹配 AI 只处理公开文本；回答核验 AI 在隔离流程中比较拾得者标准答案与失主回答 | 两个 AI 阶段必须分开，候选解释不得泄露标准答案 |
| 假设 | 候选匹配分、隐藏核验分和综合认领可信度分别计算并同时展示等级 | 防止公开相似度被误解为所有权概率 |
| 假设 | 单个 Web 应用承载失主、拾得者、管理员三种角色视图 | 符合“端”和“角色”的定义，服务端是另一个技术端 |
| 假设 | 拾得者至少能从实物中手动提取两组未公开、可观察的隐藏问答 | 没有核验基准时系统无法安全自动流转；不足时只能保存草稿 |
| 非目标 | 学校统一认证、短信验证、找回密码和第三方登录 | MVP 实现基础注册登录，但不实现生产账号体系 |
| 非目标 | 短信/邮件/微信通知、物流与线上签收 | MVP 仅在核验通过后展示拾得者联系方式，线下交接后由拾得者确认 |
| 非目标 | 图片真伪鉴定和多模态识别 | 两天内风险高，文本冲突已足以证明核心判断 |
| 非目标 | 跨校、多租户和大规模向量检索 | 模拟小数据集即可完成原型验证 |
| 非目标 | AI 自动标记实际交接完成或作法律物权裁决 | 高可信申请只能自动进入待交接，最终已认领由拾得者确认 |
| 非目标 | 多申请并发竞争、复杂撤回和申诉系统 | 不属于最小可验证主线，可作为已知限制 |
| 非目标 | 追求大量页面和视觉特效 | 评分重点是判断、取舍、验证和证据链 |

主动收窄范围、写清「两天内不做什么」是加分项，不是减分项。
