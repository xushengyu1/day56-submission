## 一、P0 / 优先级问题

### Q1 [P0/P0] "身份证件类"具体包含哪些证件？

- **当前默认**：MVP 先支持居民身份证；学生证、校园卡、护照、驾驶证暂归其他物品或后续扩展。
- **如果答案是"所有带编号证件"**：需要为每种证件定义号码格式、掩码规则、规范化逻辑和测试数据，扩大 PRD 与开发范围。
- **如果答案是"仅居民身份证"**：可以固定 18 位号码校验与掩码，测试最集中，最适合两天 MVP。
- **状态**：**已确认**，MVP 仅支持居民身份证。

### Q2 [P0/P0] 证件号码精确匹配后是否直接进入待交接？

- **当前默认**：是；"可以认领"解释为核验通过并进入待交接，仍由拾得者线下交接后标记已认领。
- **如果还需管理员审核**：自动路径消失，管理员工作量和演示流程增加，但误放行风险降低。
- **如果直接标记已认领**：会绕过真实交接确认，改变状态机和责任边界，不建议采用。
- **状态**：**已确认**，匹配成功进入待交接，不直接标记已认领。

### Q3 [P0/P0] 失主上传的可选图片是否也进入多模态提取？

- **当前默认**：不进入；只作为 PRIVATE 支持材料，MVP 的自动提取只处理拾得者图片。
- **如果进入**：需要双方图片处理、两份模型结果、额外隐私授权和视觉信息融合测试，方案 A 工作量明显增加。
- **如果不进入**：满足用户明确要求且范围可控，但放弃利用失主旧照片自动补充描述。
- **状态**：**已确认**，失主图片不进行多模态提取。

### Q4 [P0/P0] 证件公开页展示掩码号码还是完全不展示号码？

- **确认答案**：公开页展示掩码号码，MVP 采用"前 3 位 + 后 4 位，其余 `*`"，同时展示脱敏图片。
- **如果完全不展示**：隐私最强，但失主发现候选的效率下降，候选主要依赖时间地点。
- **如果展示较多位数**：发现效率提高，但试探和身份泄露风险上升，需要更严格限流。
- **影响**：改变 PUBLIC DTO、图片脱敏、前端、隐私测试和答辩风险说明。
- **状态**：**已确认**。

## 二、产品与规则问题

### Q5 [P1] 拾得者是否必须逐位确认模型提取的证件号码？

- **当前默认**：必须确认并可修改，未确认只能保存草稿。
- **方案影响**：若允许模型结果直接发布，开发更少但号码误识别会导致真实失主无法核验，且证据链缺少责任确认。
- **状态**：**已确认**，拾得者必须逐位确认并可修改；未确认只能保存草稿。

### Q6 [P1] 证件号码允许尝试几次？

- **当前默认**：同一账号对同一候选最多 2 次。
- **方案影响**：次数更多会增加枚举风险；次数更少会放大输入错误。改变状态机、限流和失败测试。
- **状态**：**已确认**，同一账号对同一候选最多 2 次。

### Q7 [P1] 多条招领记录具有同一号码时如何处理？

- **当前默认**：禁止自动待交接，转管理员检查重复记录和审计信息。
- **方案影响**：若任选一条自动通过可能造成错误交接；若全部拒绝则真实失主无法继续。
- **状态**：**已确认**，禁止自动待交接并转管理员检查重复记录与审计信息。

### Q8 [P1] 号码格式如何规范化？

- **当前默认**：去除空格和分隔符、字母转大写；居民身份证末位 `x/X` 统一为 `X`。
- **方案影响**：支持多证件类型时必须按类型实现不同规范化器和测试集。
- **状态**：**已确认**，按居民身份证规则执行。

### Q9 [P1] 其他物品需要几个隐藏特征？

- **确认答案**：至少 1 段可生成 2～3 个开放式问题的隐藏描述；若无法形成有效问题则保存草稿。
- **方案影响**：提高门槛能降低冒领，但会增加拾得者发布负担；降低门槛会增加管理员复核。
- **状态**：**已确认**；问题质量仍需样例验证。

## 三、技术与隐私问题

### Q10 [P1] 多模态模型选择哪一种？

- **当前默认**：优先验证官方支持图片理解和 OpenAI 兼容接口的 MiMo-V2.5；必须准备 mock/手工降级。
- **方案影响**：更换为 OCR 专用模型会提高证件文字提取针对性但增加第二模型；本地模型会增加部署成本。
- **状态**：**已确认**，优先验证 MiMo-V2.5，并保留 mock/手工降级。

### Q11 [P1] 证件号码如何保存以支持精确比较？

- **当前默认**：应用层规范化后计算 HMAC-SHA256，数据库保存 HMAC 和掩码，不保存普通日志明文。
- **方案影响**：若保存可逆密文，需要密钥轮换和解密授权；若只保存普通哈希，固定格式号码可能被离线枚举。
- **状态**：**已确认**，使用应用层 HMAC-SHA256。

### Q12 [P1] 身份证件原图保存多久？

- **当前默认**：MVP 保存到记录关闭，用于演示权限与审计；候选页只访问脱敏副本。
- **方案影响**：立即删除原图可降低泄露面，但无法复核识别和脱敏；长期保存则增加安全责任。
- **状态**：**已确认**，保存到记录关闭。

### Q13 [P2] 图片脱敏由模型、规则还是拾得者手工框选？

- **当前默认**：模型/OCR 给出区域，服务端生成遮挡副本，拾得者预览确认；失败时手工框选或不公开图片。
- **方案影响**：纯模型最快但风险不可控；纯手工最稳定但交互成本更高；混合方案测试最多但安全性最好。
- **状态**：**已确认**，采用模型/OCR 定位、服务端生成遮挡副本、拾得者预览确认；失败时手工框选或不公开。

### Q14 [P2] 多模态提取失败时是否允许无图发布？

- **当前默认**：原图已上传即可手工填写后发布；不要求模型成功。
- **方案影响**：若模型失败即禁止发布，系统可用性受外部 API 影响；若允许无图，违反拾得者必须上传图片的要求。
- **状态**：**已确认**，保留已上传原图并允许手工填写后发布。

### Q15 [P2] 管理员能否查看完整证件号码和原图？

- **当前默认**：管理员列表只看掩码和事件；仅在明确授权的异常复核操作中临时查看原图，完整号码默认仍不可见。
- **方案影响**：完全可见会扩大泄露面；完全不可见会降低异常复核能力，需要更强审计工具。
- **状态**：**已确认**，管理员列表只看掩码和事件；明确授权时临时查看原图；完整号码默认不可见。
