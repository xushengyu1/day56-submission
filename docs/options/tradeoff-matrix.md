## 关键取舍说明

### 取舍 1：LLM 自动生成问题 vs 拾得者手动编写

- **选择 LLM 自动生成**：拾得者只需上传隐藏特征（如"伞套内侧写有SZY"），LLM 自动生成开放式问题
- **代价**：拾得者对问题的控制力降低；LLM 生成的问题可能不完全符合拾得者预期
- **缓解**：拾得者可查看生成的问题并确认；隐藏特征的质量是关键输入

### 取舍 2：React SPA vs SSR

- **选择 React SPA**：组件化交互，用户体验最佳
- **代价**：需要 Vite 构建工具、JWT 认证、CORS 配置，开发成本高于 SSR
- **缓解**：Vite 热重载加速开发；JWT 标准方案成熟；前后端分离架构清晰

### 取舍 3：外部 API 依赖 vs 本地模型

- **选择外部 API（text-embedding-v4 + mimoV2.5-pro）**：模型质量最高，无需本地资源
- **代价**：需要网络可达；API 超时需降级处理
- **缓解**：Embedding 超时降级为关键词匹配；核验超时转管理员复核

### 取舍 4：向量匹配 vs LLM 直接匹配

- **选择 pgvector 向量匹配**：利用已确认的 pgvector 能力，匹配延迟低
- **代价**：向量匹配只能捕捉语义相似度，无法像 LLM 那样理解复杂逻辑关系
- **缓解**：TOP-5 候选已足够覆盖；结合时间/地点规则评分补充
