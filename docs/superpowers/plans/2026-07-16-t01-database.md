# T01 Database Schema and Migrations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (recommended) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the current PRD data contracts, PostgreSQL enums, core tables, constraints, and six reversible Alembic migrations.

**Architecture:** SQLAlchemy models are split by domain and imported by `app/db/models.py`. Alembic migrations mirror the order fixed in `dev.md`; a local `VectorType` maps metadata to PostgreSQL `vector` without exposing vendor details to business modules.

**Tech Stack:** Python 3.11+, SQLAlchemy 2.x async, Alembic 1.16+, PostgreSQL/pgvector, pytest, Docker Compose.

## Global Constraints

- Preserve T00 health behavior and run its tests after T01 changes.
- No schema implementation before integration tests fail for the intended missing behavior.
- Use only synthetic values; do not place identity numbers, hidden answers, tokens, or secrets in tests, migrations, logs, or evidence.
- Use exactly six migration revisions in the order fixed by `dev.md`.
- Do not create an ANN index or uniqueness on the identity HMAC.
