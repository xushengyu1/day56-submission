## 二、正向场景

### TC-P01：高可信自动待交接（主路径）

**前置条件**：失主和拾得者已注册登录；拾领记录已发布且隐藏问答满足门槛。

| 步骤 | 用户动作 | 预期系统行为 | 预期数据变化 |
|---|---|---|---|
| 1 | 拾得者发布招领：黑色折叠伞，教学楼 B 区 3F，7月16日上午 | 保存招领记录，状态=待匹配；embedding 生成成功 | `item_record` 新增，`text_embedding` 非空 |
| 2 | 失主发布失物：黑色短柄折叠伞，教学楼附近，7月16日上午 | 保存失物记录，触发候选匹配 | `item_record` 新增，`match_candidate` 新增 |
| 3 | 失主查看候选列表 | 展示候选，匹配分≥80，显示匹配点/冲突点/保留原因 | 候选分≥80，等级=高 |
| 4 | 失主点击认领，回答隐藏问题（准确描述隐藏特征） | 提交认领申请 | `claim_application` 新增，状态=AI核验中 |
| 5 | 系统自动核验 | 隐藏核验分≥85，综合可信度≥85，无硬冲突 | 状态→自动核验通过→待交接 |
| 6 | 失主查看待交接状态 | 展示拾得者已授权的联系方式 | 联系方式可见 |
| 7 | 拾得者标记已认领 | 状态→已认领 | `operation_log` 记录交接 |

**验证要点**：
- [ ] 候选匹配分≥80
- [ ] 隐藏核验分≥85
- [ ] 综合可信度≥85
- [ ] 自动进入待交接（非人工审核）
- [ ] 联系方式仅在待交接后展示
- [ ] 仅拾得者可标记已认领
- [ ] 完整审计日志

### TC-P02：近似描述仍能匹配

**场景**：失主写"深色短柄伞"，拾得者写"黑色折叠伞"。

| 步骤 | 用户动作 | 预期系统行为 |
|---|---|---|
| 1 | 拾得者发布：黑色折叠伞 | 保存成功 |
| 2 | 失主发布：深色短柄伞 | 触发匹配 |
| 3 | 查看候选 | pgvector 语义相似度识别"深色"≈"黑色"，"短柄伞"≈"折叠伞"；候选分≥60 |

**验证要点**：
- [ ] 语义匹配成功召回（候选分≥60，等级=中或高）
- [ ] 匹配点展示"颜色和类型接近"
- [ ] 不因措辞差异排除真实候选

### TC-P03：地点偏差但保留候选

**场景**：失主写"三楼"，拾得者写"二楼楼梯口"。

| 步骤 | 用户动作 | 预期系统行为 |
|---|---|---|
| 1 | 拾得者发布地点：教学楼 B 区 2F 楼梯口 | 标准化地点代码=TEACHING_B_2F_STAIR |
| 2 | 失主发布地点：教学楼三楼 | 标准化地点代码=TEACHING_B_3F |
| 3 | 查看候选 | 地点接近度=同楼/相邻楼层=14分；冲突点展示"楼层不一致"；保留原因展示"相邻区域，物品可能被移动" |

**验证要点**：
- [ ] 地点偏差未导致候选被排除
- [ ] 冲突点明确展示
- [ ] 保留原因合理

## 三、反向场景

### TC-N01：公开相似但隐藏特征冲突

**场景**：两条黑色折叠伞，时间和地点接近，但隐藏标记不一致。

| 步骤 | 用户动作 | 预期系统行为 |
|---|---|---|
| 1 | 拾得者发布：黑色折叠伞，隐藏答案="伞套内侧写有 SZY" | 保存成功 |
| 2 | 失主发布：黑色折叠伞 | 候选匹配分高（≥80） |
| 3 | 失主认领，回答="伞套内侧没有任何标记" | 隐藏核验分=0（冲突） |
| 4 | 系统路由 | 不自动通过，进入管理员复核 |

**验证要点**：
- [ ] 公开高分不导致自动通过
- [ ] 隐藏冲突被正确识别
- [ ] 进入管理员复核（非自动拒绝）

---

### TC-N02：关键问题回答错误

**场景**：拾得者标记为关键问题的问题，认领人回答错误。

| 步骤 | 用户动作 | 预期系统行为 |
|---|---|---|
| 1 | 拾得者设置关键问题（is_critical=true） | 保存成功 |
| 2 | 认领人回答关键问题错误 | 单题结果=冲突 |
| 3 | 系统路由 | 关键问题冲突直接禁止自动流转，进入管理员复核 |

**验证要点**：
- [ ] 关键问题冲突触发转管理员
- [ ] 不因其他问题高分而自动通过

---

### TC-N03：多人认领同一物品

**场景**：两个不同用户同时认领同一招领记录。

| 步骤 | 用户动作 | 预期系统行为 |
|---|---|---|
| 1 | 用户 A 认领并回答隐藏问题 | 创建认领申请 A |
| 2 | 用户 B 认领并回答隐藏问题 | 创建认领申请 B |
| 3 | 系统路由 | 两个申请均进入管理员复核（多人认领=强制人工） |

**验证要点**：
- [ ] 多人认领检测生效
- [ ] 两个申请均不自动通过
- [ ] 管理员可查看两个申请的对比材料

## 四、边界场景

### TC-B01：阈值边界（候选分=80）

**场景**：候选匹配分恰好等于自动通过阈值 80。

**验证要点**：
- [ ] 候选分=80 时仍满足高可信门槛（≥80 含等于）
- [ ] 候选分=79 时不满足高可信门槛

### TC-B02：阈值边界（隐藏核验分=85）

**场景**：隐藏核验分恰好等于自动通过阈值 85。

**验证要点**：
- [ ] 核验分=85 时仍满足门槛
- [ ] 核验分=84 时不满足门槛

### TC-B03：隐藏问答刚好两组

**场景**：拾得者只设置两组隐藏问答，刚好满足发布门槛。

**验证要点**：
- [ ] 两组问答可以发布
- [ ] 一组问答时只能保存草稿

### TC-B04：回答次数限制

**场景**：同一认领申请提交第 2 次回答。

**验证要点**：
- [ ] 第 1 次回答正常提交
- [ ] 第 2 次回答正常提交
- [ ] 第 3 次回答被拒绝

## 五、失败场景

### TC-F01：AI Embedding API 超时

**场景**：OpenAI Embedding API 调用超时（>5 秒）。

**验证要点**：
- [ ] 降级为关键词匹配
- [ ] 候选结果标记"AI 不可用，使用规则匹配"
- [ ] 用户数据不丢失
- [ ] 错误日志记录

### TC-F02：AI 核验 API 超时

**场景**：OpenAI GPT API 调用超时（>10 秒）。

**验证要点**：
- [ ] 核验分按"无法判断"处理
- [ ] 进入管理员复核
- [ ] 不伪造 AI 结果
- [ ] 错误日志记录

### TC-F03：AI 输出格式异常

**场景**：LLM 返回的 JSON 不符合预期结构。

**验证要点**：
- [ ] 重试 1 次
- [ ] 仍失败则按"AI 异常"转管理员
- [ ] 保存原始异常输出到日志

## 六、安全场景

### TC-S01：候选页数据隔离

**场景**：普通用户通过 API 候选接口获取数据。

**验证要点**：
- [ ] 响应只包含 PUBLIC 字段
- [ ] 不包含 MATCH_ONLY 原始值（如精确坐标、向量）
- [ ] 不包含 VERIFICATION 标准答案
- [ ] 不包含 PRIVATE 联系方式

### TC-S02：隐藏答案泄露检查

**场景**：拾得者设置的问题包含标准答案关键词。

**验证要点**：
- [ ] AI 质量检查提示"问题可能泄露答案"
- [ ] 拾得者可选择修改或确认
- [ ] 确认后仍可发布（最终由拾得者决定）

### TC-S03：联系方式展示时机

**场景**：认领尚未进入待交接时，失主尝试查看联系方式。

**验证要点**：
- [ ] 联系方式不可见
- [ ] 仅待交接状态 + 拾得者已授权时展示

## 3. 模型 spike 最小数据集

至少准备 8 张不含真实个人数据的合成/脱敏图片：

1. 清晰居民身份证样例 2 张；
2. 模糊、反光身份证样例 2 张；
3. 普通物品（雨伞、水杯、耳机）3 张；
4. 不相关或损坏图片 1 张。

每张记录：期望类型、期望名称、期望公开特征、号码期望（仅合成数据）、实际结构化输出、置信度、拾得者需修改字段、耗时和错误。
