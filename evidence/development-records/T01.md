## Red 记录

初次运行：

```bash
cd src/backend
../../.venv/bin/pytest tests/integration/db -q
```

结果：收集阶段 `ModuleNotFoundError: No module named 'app.db'`，说明模型/迁移契约尚未实现。

模型加入后，旧分支遗留数据库只包含旧表，测试以 `UndefinedTableError` 失败；同时 session 级 async engine 与 pytest-asyncio 独立事件循环不兼容，出现 `Future attached to a different loop`。将集成 fixture 调整为 function 作用域后，错误只剩预期的缺表状态；该修复不改变生产连接逻辑。

向量 round-trip 测试首次失败：asyncpg 报 `expected str, got list`。为 `VectorType` 增加 list 到 `[0.25,-0.5,0.75]` 文本的 bind processor 后通过。

## 迁移与 metadata 验证

```bash
docker compose up -d --wait postgres
DATABASE_URL=postgresql+asyncpg://app:app@127.0.0.1:55432/lost_found \
  ../../.venv/bin/alembic downgrade base
DATABASE_URL=postgresql+asyncpg://app:app@127.0.0.1:55432/lost_found \
  ../../.venv/bin/alembic upgrade head
DATABASE_URL=postgresql+asyncpg://app:app@127.0.0.1:55432/lost_found \
  ../../.venv/bin/alembic check
```

结果：PostgreSQL 容器 healthy；六段 migration upgrade 和 downgrade 均退出 0；`alembic check` 输出 `No new upgrade operations detected.`。测试检查了 vector 扩展、`item_records.embedding` 的 `vector` 类型、核心表、Top 5/HMAC/尝试/审计/活动复核索引，以及 migration 中没有完整身份证号码字面量。
